= Stale Reference Tombstones and Path Migrations

This file is the audit record for the `+SD022+` / `+SD007+` structural-drift
work (GitHub issue #242). It has three jobs:

. record every stale path that was *migrated* to a verified current path;
. record every stale path that was *deliberately left in place*, with the
  reason (a tombstone), so the same alert is not re-triaged from scratch;
. record the targets that were never a rename at all and therefore need
  real follow-up.

The originating classification is
`+docs/reports/2026-06-06-hypatia-alert-classification.adoc+`, which bucketed
28 `+SD022+`/`+SD007+` alerts as "lifecycle hygiene — PR-only
documentation/state cleanup". This file is that cleanup's receipt.

== The drift class: `.md` → `.adoc`

Almost all of the stale references were one mechanical class. The repository
publishes its long-form documentation as AsciiDoc, but a large set of
references still pointed at the `.md` spelling of the same filename. In every
case the `.adoc` counterpart existed at the identical path, so the
replacement target is *verified by existence*, not inferred.

*502 references were retargeted across 109 files.* No file was renamed,
created, or deleted to make an alert go away. The work landed in two passes:
the 16 highest-volume classes first, then a systematic sweep for every
remaining `.md` reference that had a verified `.adoc` counterpart.

Three of these were load-bearing beyond navigation and are called out
explicitly:

* `+.github/canonical-references/prover-counts.yml+` declared
  `+canonical_pointer: docs/PROVER_COUNT.md+`. Because that path did not
  exist, the R5a canonical-reference guardrail was pointing at nothing.
  It now points at the file that exists.
* The same file's `+scope.include+` list named `+AUTHORS.md+` and
  `+CODE_OF_CONDUCT.md+`, neither of which exists — so those two surfaces
  were outside the guardrail's scan. Both now name the `+.adoc+` files.
* `+Justfile+`'s `+er-schema-drift-check+` recipe ran `+sha256sum+` against
  `+docs/architecture/VERISIM-ER-SCHEMA.md+`, so the recipe failed on a
  missing file. It now hashes the real document. No stored hash was
  invalidated: `+.machine_readable/er-schema.sha256+` does not exist, so
  there was no pinned constant to update.

=== Guarding against over-reach

Two classes of false positive were excluded mechanically.

*Names that merely contain a migrated basename* were left untouched:
`+FUTURE_DEVELOPMENT_ROADMAP.md+`, `+PROVER_EXPANSION_ROADMAP.md+`,
`+CORRECTNESS-ARCHITECTURE.md+`, `+ECHIDNA-TODO.md+`.

*References to files that genuinely exist as `+.md+`* were left untouched —
this is the reason the sweep checks target existence rather than blindly
rewriting every `.md` it sees. 47 references fall in this class across the
21 tracked `+.md+` files: `+SECURITY.md+`, `+CLAUDE.md+`, `+GEMINI.md+`,
`+.github/CONTRIBUTING.md+`, `+.github/PROVEN-INTEGRATION.md+`,
`+docs/wiki/*.md+` and the GitLab issue/MR templates. In particular
`+SECURITY.md+` coexists with `+SECURITY.adoc+` and is *not* stale; an
earlier, looser version of this sweep rewrote
link in `+AUTHORS.adoc+` (`+link:SECURITY.md+`) and was caught by this check.

== Reproducing the check

[source,bash]
----
# 1. No migrated .md reference should remain outside the tombstones below.
grep -rnE '(^|[^A-Za-z0-9_-])(PROVER_COUNT|CORPUS-ADAPTERS|VERISIM-ER-SCHEMA|ROADMAP|CHANGELOG|ARCHITECTURE|DEBT|ENV-VARS|PROOF-NEEDS|HANDOVER-INDEX|SPARK_ADOPTION_PLAN|S5-VERIFICATION-RUNBOOK|TYPE-DISCIPLINE-EMBEDDING|L3-LIVE-PROVER-CI-PROMPT)\.md' . \
  | grep -v '^./.git/'

# 2. Every .adoc target referenced by a changed file must exist.
#    Resolve each reference relative to both the referencing file and the repo root.

# 3. A .md reference is only rewritten when the .md file is absent AND
#    the .adoc counterpart is present. Anything else is a tombstone below.
----

== Follow-ups that are *not* renames

These targets were never renamed — they simply do not exist. They need a
decision, not a search-and-replace, and are deliberately out of scope here.

=== `.hypatia-ignore` exemptions all point at deleted files

All 33 entries in `+.hypatia-ignore+` exempt `+banned_language_file+` findings
for `+.res+` sources that no longer exist (`+src/rescript/+` and
`+src/provers/+` are gone from the tree). Check it with:

[source,bash]
----
while read -r l; do case "$l" in \#*|'') continue;; esac
  p="${l#*:}"; [ -e "$p" ] || echo "dead exemption: $p"; done < .hypatia-ignore | wc -l
# => 33
----

The file's own header says each entry "gets removed as the matching `+.res+`
file is migrated to AffineScript or deleted". Per #242's safety note, a
policy/state file is not rewritten to clear alerts, so this is recorded
rather than changed. Emptying the ledger is a one-line owner decision.

=== Remaining dangling documentation targets

An independent scan for repository-internal path references that resolve to
nothing found *108* remaining targets, down from 129 before this change. The
largest are pointers at files that do not exist in any spelling — for
example `+verification/pareto.rs+`, `+verification/portfolio.rs+`,
`+verification/confidence.rs+`, `+scripts/retrain_from_verisim.jl+`,
`+docs/buchholz-plan.adoc+`, `+src/rust/core.rs+` and
`+src/rust/provers/your_prover.rs+` (the last is likely intentional as an
extension template). These are a separate alert family from the `.md`/`.adoc`
drift and should be triaged on their own.
