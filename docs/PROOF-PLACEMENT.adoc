= Proof placement by property
:toc:

This ledger records where each existing engineering proof statement of ECHIDNA
belongs, under owner ruling 2026-11-16 ("split by property"; see the
classification paragraph under R4 in `link:PROOF-STATUS.adoc[PROOF-STATUS]`).

[cols="1,4",options="header"]
|===
|Home |Meaning
|`rust` |A property of one shipped Rust function or type. Proved on the Rust with Creusot/Pearlite and Verus (PROOF-POLICY §1.2). The obligation column gives the contract.
|`idris2` |A fact about an interface, ABI, wire format or cross-language encoding.
|`agda-theory` |Holds for any implementation. Stays Agda, rechecked in Rocq and Lean.
|`retire` |Proves nothing about the system: true by definition, an instance of `cong`, a toy counterexample, or a model of behaviour the Rust lacks. The obligation column names its successor, if any.
|===

*How this was produced, and what it is not.* For each area, one agent classified every
top-level statement against the source and the Rust. A second agent tried to
refute each verdict. A third reconciled the two against the source.
All three only read the source. Nothing was built or run: no Agda, Lean, Idris 2,
Creusot, Verus or cargo. This ledger is a placement, not a receipt. No row
changes a status token in PROOF-STATUS. A `rust` row is an open obligation
until a Creusot run *and* a Verus run discharge it.

Rows marked as defects in "Model gaps" are source readings. Each needs a
failing test or a repro before it is treated as a confirmed bug.

=== Model gaps

* Agda check maps an uninitialised manifest to Missing (meta-checker/src/Echidna/Integrity.agda:81). The Rust returns Uninitialized for a found binary with a placeholder hash (src/rust/integrity/solver_integrity.rs:240-263) and Missing only when no binary is found (:220-237).
* Agda takes the digest comparison as a parameter with an assumed soundness field (Integrity.agda:47-51). The Rust has one fixed comparison, String == (solver_integrity.rs:277). The Agda has no file, no hash function and a three-constructor result (Integrity.agda:64-67); the Rust enum has five variants.
* Lean omits Unchecked (verification/proofs/lean4/IntegrityVerification.lean:128-132). The Rust get_status returns it (solver_integrity.rs:351) and is_solver_safe accepts it (:359). This is what makes verify_exhaustive (lean:229) vacuous.
* Lean FileResult is found-with-bytes or notFound (IntegrityVerification.lean:136-138). The Rust has a third case, found but unreadable: with a placeholder hash it still returns Uninitialized with both hashes None (solver_integrity.rs:246-263); with a real hash it returns Missing (:298-309).
* Lean ManifestHash is a typed sum (IntegrityVerification.lean:111-113). The Rust holds a String, tests starts_with("PLACEHOLDER") (solver_integrity.rs:240) and compares hex with String equality (:277). An upper-case, padded or truncated manifest digest gives Tampered, so verify_complete (lean:195) does not hold of the Rust for digests equal as bytes but not as strings.
* Lean cacheInvariant says the cache holds the BLAKE3 of the bytes at the last successful full verification (IntegrityVerification.lean:302-314). The Rust writes the cache in the placeholder arm (solver_integrity.rs:250-253) and before the comparison (:272-275), so also on Tampered; the BLAKE3 comes from a second file read (:125) separate from the SHAKE read (:111); nothing is written in the SHAKE-read-fails arm (:298-309); a stale entry survives a later Missing result.
* Lean quickReverify is a total Bool over given bytes (IntegrityVerification.lean:321-322). The Rust quick_reverify re-resolves the path (solver_integrity.rs:329), so it may hash a different file; it has four Err paths (:319, :327, :330, :332); the cache lock is dropped at :321 before hashing, so Ok(true) relates to the value read at entry.
* Lean integrityToBool is 'status = verified' (IntegrityVerification.lean:364-365). The Rust gate (src/rust/dispatch.rs:648-661, 858-871, 1009-1022) accepts Verified or Uninitialized (:655-656), gives true when no report name matches (:658) and true when no checker is attached (:660). trust_gate_iff_verified (lean:369) is false of the Rust.
* The fourth fail-open path in the ledger (docs/PROOF-STATUS.adoc:181-184, 'a verify_all() error read as an empty report') is unreachable: verify_all has no error path and its only return is Ok(results) (solver_integrity.rs:164-209, :208). The unwrap_or_default at dispatch.rs:649 is dead. Three fail-open paths are reachable, not four.
* The gate matches reports by format!("{:?}", prover_kind).to_lowercase() (dispatch.rs:650-653). Manifest keys lean4 (config/solver-manifest.toml:18) and hol_light (:48) never match ProverKind::Lean or ProverKind::HOLLight (crates/echidna-core/src/prover_kind.rs:27, :34), so a Tampered report for those two still gives true. ProverKind::MizAR (prover_kind.rs:324) lower-cases to 'mizar' and reads the Mizar entry's report (solver-manifest.toml:54). find takes the first match. Read from source, not exercised. No proof file states this name mapping.
* Collision resistance is modelled as injectivity (IntegrityVerification.lean:279-280, 328-329). That is false of any fixed-length digest over unbounded input; the Lean digest types are unbounded lists (lean:73-75, 78-80), which hides it. PI-7 and PI-9 rest on it.
* SPARK Aggregate_Safe and Cap_At_Tampered (spark/solver_integrity/solver_integrity.ads:107-108, 126-129) model a fleet-level decision. The Rust has none: verify_all counts and logs (solver_integrity.rs:179-206) and dispatch reads one report (dispatch.rs:651-653).
* SPARK Is_Safe (solver_integrity.ads:84-85) mirrors is_solver_safe (solver_integrity.rs:355-361), which has no caller and accepts Unchecked; the dispatch gate (dispatch.rs:655-656) uses a different set. Two 'safe' predicates exist in the Rust.
* DispatchOrdering models Integrity as stage 0, before every other stage (proofs/agda/DispatchOrdering.agda:34-35, 81-104; verification/proofs/idris2/DispatchOrdering.idr:15, 23, 41). The Rust runs the integrity check as Step 6 (dispatch.rs:647), after the prover run at Step 3 (:611).
* None of the modelled code runs in the shipped binary: with_integrity_checker (dispatch.rs:317) has no caller, and all 17 entries of config/solver-manifest.toml hold PLACEHOLDER_COMPUTE_ON_FIRST_RUN, so solver_integrity_ok is always true at run time. quick_reverify (solver_integrity.rs:315) and is_solver_safe (:355) have no caller. Contracts on verify_solver do not close DEBT D9.
* verify_solver (solver_integrity.rs:212) is async, takes a tokio RwLock, reads the filesystem and spawns `which` (:147), so the rust rows assume a pure core is extracted and called by the shipped function. === Model gaps

* Signature: both proofs model a one-argument map Nat -> TrustLevel with the range fixed at [Level1, Level5] (meta-checker/src/Echidna/ClampTrust.agda:50; verification/proofs/idris2/ClampTrustBounds.idr:78). The Rust is clamp_trust(level, min_level, max_level), all TrustLevel, with precondition min_level <= max_level (crates/echidna-core-creusot/src/lib.rs:278-290). Nothing in the proofs matches the two range arguments or the precondition, and at [Level1, Level5] the Rust clamp is the identity.
* The Rust clamp_trust has no caller: grep over echidna and its sibling estate checkouts finds only the definition (crates/echidna-core-creusot/src/lib.rs:282) and its own test PO-7 (:580-592). Under its precondition it returns what the derived Ord::clamp returns (TrustLevel derives Ord at lib.rs:91-93).
* No integer-to-level conversion exists in shipped Rust (no From<u8>, TryFrom<u8> or from_u8 for TrustLevel in src/ or crates/). The Cap'n Proto UInt8 fields have no Rust reader (crates/echidna-wire/schemas/proof.capnp:15, :27; prover.capnp:46; schemas/echidna.capnp:32; the only trust call is set_trust_level(3) in a test, crates/echidna-wire/src/lib.rs:91). So the model's decode of 0 to Level1 (ClampTrust.agda:51, :124; ClampTrustBounds.idr:79, :157) and of 5 and above to Level5 (ClampTrust.agda:56, :130, :135; ClampTrustBounds.idr:84, :163, :301) describes nothing.
* Correction to the first pass ('the Rust has no decoder at all'): the only decoder is the derived serde::Deserialize (crates/echidna-core-creusot/src/lib.rs:91-93), used by DispatchResult and DispatchConfig (src/rust/dispatch.rs:65-70, :109-114; decode test :1293-1296). === Model gaps

* ConfidenceLattice.computeTrustLevel is the pre-#477 rule, though its docstring says it mirrors the Rust exactly (verification/proofs/lean4/ConfidenceLattice.lean:150-168). The kernel (crates/echidna-core-creusot/src/lib.rs:346-399) needs has_certificate for Levels 4 and 5 and min(small_kernel_confirmations, confirming_provers) >= 2 for Level 5. With integrity ok, Safe axioms and a small kernel: cp=2, verified, no certificate gives Lean Level5 but Rust Level3; cp=1, verified, no certificate gives Lean Level4 but Rust Level2; cp=2, certificate, verified, small_kernel_confirmations=1 gives Lean Level5 but Rust Level4.
* The Lean TrustFactors has no small_kernel_confirmations field and a free Bool is_small_kernel (ConfidenceLattice.lean:136-148). The Rust has ProverClass in the kernel, derived from ProverKind by a twelve-prover table in the wrapper (src/rust/verification/confidence.rs:60-85). The wrapper and the table are unmodelled.
* The Lean order on TrustLevel is defined as value a ≤ value b (ConfidenceLattice.lean:46-52). The Rust order is the derived Ord (crates/echidna-core-creusot/src/lib.rs:91-93). Nothing states that the two agree, so the Lean order laws are facts about Nat, not about the Rust `<=` used by the minimum-trust gate (src/rust/dispatch.rs:680, :1038).
* Levels 4 and 5 are modelled but no shipped caller can reach them: all three dispatch call sites pass has_certificate false, certificate_verified false and small_kernel_confirmations 0 (src/rust/dispatch.rs:666-669, 875-878, 1026-1029). Shipped dispatch returns only Level1, Level2 or Level3.
* The integrity cap's hypothesis is rarely reachable: solver_integrity_ok is true when no checker is configured, when the prover is not in the manifest, when verify_all fails (unwrap_or_default) and when the status is Uninitialized (src/rust/dispatch.rs:648-662, and the same pattern before :875 and :1026).
* Lean uses Nat; the Rust uses u32, u64, usize and u8. adding_prover_monotone adds 1 with no overflow (ConfidenceLattice.lean:213-215); on the Rust it needs confirming_provers < u32::MAX.

=== Open questions
