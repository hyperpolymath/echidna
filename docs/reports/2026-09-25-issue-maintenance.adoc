== Hypatia classification (#239, #240)

[source,bash]
----
# For a fresh report, use the scanner's actual absolute checkout root:
jq --arg root "$PWD" -f scripts/ci/triage-hypatia.jq findings.json > triaged.json

# Reproduce the archived-report inventory (NOT a fresh scan):
jq --arg root /home/hyperpolymath/dev/repos/echidna \
  -f scripts/ci/triage-hypatia.jq reports/hypatia-findings-v4.json > triaged.json
jq 'group_by(.triage.risk_class) | map({risk: .[0].triage.risk_class, count: length})' triaged.json
----

The archived v4 report contains 148 findings: 36 runtime-availability,
17 FFI-memory-safety, 4 proof-soundness, 76 language-migration, 14 other,
and 1 unclassified-code-safety. These are historical, not current alert counts.

The original object (including severity, file, reason and any supplied line)
is retained. Only a `triage` annotation is added. Line numbers absent from
the input remain null; none are invented from an old report against new source.
Runtime findings under `tests/`, `benches/`, and `fuzz/` get a lower
review priority with a rationale, NOT a lowered scanner severity or suppression.
Mixed production modules containing inline tests remain unreviewed production.
Proof and FFI obligations keep expert routing even in test directories.

`panicbot` is the runtime review route, `echidnabot` the memory/proof route,
and `rhodibot` the migration route. Routing is advisory data, not a claim
that those bots have reviewed the code. No default-value substitutions or
whole-tree mechanical safety rewrites are performed.
