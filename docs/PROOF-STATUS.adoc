== Vocabulary

Closed set, `+PROOF-POLICY.adoc+` §5. Machine-readable ledgers use the
lowercase token; prose may use the label.

[width="100%",cols="22%,16%,62%",options="header"]
|===
|Token |Label |Means

|`+proven+` |PROVEN
|Machine-checked with no escape hatch, trust boundary named. A bounded check is
not this row.

|`+proven-with-postulates+` |PROVEN-WITH-AXIOMS
|A kernel checked it and it rests on named necessary axioms, listed here.

|`+tested-only+` |TESTED
|Checked on a bounded or sampled domain; bounds given.

|`+argued+` |ASSUMED
|A stated hypothesis, or a transcription no kernel has checked. Includes "the
CI gate exists and the authors say it passes" when no receipt is cited.

|`+open+` |OPEN
|Not done.
|===

=== Relation to the Proof Witness Grades (PWG)

`+PROOF-POLICY+` §8 (owner ruling 2026-11-04) is normative for grades. A PWG
says how many independent machine-checked witnesses a *theory* theorem has:
`+PWG-3+` (Agda source checked under the §2.1 invocation, with a receipt),
`+PWG-2i+` (plus one counted Rocq or Lean leg), `+PWG-2ii+` (plus both),
`+PWG-1+` (every counted witness has a current per-commit receipt from a
headless, isolated, pinned run). Always write the `+PWG-+` prefix.

* *Engineering proofs are not graded* (§8.1). Creusot, Verus, SPARK and Idris 2
  results, and Agda statements about ECHIDNA's own functions and types, use the
  §5 tokens only. In this file that covers R1, R2, R3, R9, R10, R12 and most of
  R4. A theory theorem below `+PWG-3+` is `+ungraded+`.
* A recheck leg counts only when its kernel accepted it *and* its §2.2
  correspondence is `+RECONCILED+`. Until then it is not a witness.

Grades are derived from receipts, never asserted, and are never flattened into
a percentage. See R5 and R6.

|R9. E11 solver-integrity soundness
|`+proven+`
|`+meta-checker/src/Echidna/Integrity.agda+`, inside the R4 receipt. States the
obligation that had no Agda record: verification requires an initialised
manifest; verification means the recorded digest was matched; a binary with
a different digest is never verified; an uninitialised manifest never
verifies. Digest-comparison soundness is a record *field*, not a postulate,
so the matching theorem is explicitly conditional on that field.
`+sharpness-blocks-soundness+` refutes the exact soundness property for an
accept-everything comparator.
**Scope of the model (from review, 2026-11-01):** a binary is modelled by its
digest alone, so these are statements about *digests*, not bytes.
"Substituted" means "a binary whose digest differs", and two binaries colliding
on a digest are not distinguished by this model. `+≈d-sound+` says that an
accepted comparison implies equal digests; the model contains neither
binary contents nor a hashing function. Content-level collision resistance
is outside this model, not a property established or assumed by that field.

|**Specification, not implementation.** Rust returns
`+IntegrityStatus::Uninitialized+` for an installed binary with a placeholder
manifest, and dispatch can permit that status. It does not report
`+Verified+` in that case. Agda proves a property of its `+check+` function
and has no dispatch-permission decision. DEBT D9 is therefore a source
comparison, not a machine-checked discrepancy or refinement proof. The Rust
implementation leg remains open under R1's Creusot obligation.

== Not obligations

`+PROOF-POLICY+` §3: "`Corpora that exist to exercise provers are not
obligations. echidna's `+proofs/<prover>/+` trees and similar fixtures are test
material for a multi-prover system and are outside this policy.`"

So the sixteen `+proofs/<prover>/+` directories and `+training_data/+` carry no
row. They exercise parsers and backends. Listing them is deliberate: an absent
row should read as *out of policy*, not *forgotten*. The same holds for
`+archive/logtalk/+` (dead, quarantined) and for `+echidna-playground/+`.

R6 used to cite a corpus artefact as covering a real obligation. It now cites
`+meta-checker/src/Echidna/Composition.agda+`, and both corpus files say in
their headers that they are not E9 evidence.

== What this file does not do

It is not a release gate and not a CI result. A `+proven+` row here would never
mean "ECHIDNA is verified" — it would mean one named obligation was discharged
by one named tool with its boundary written down. Nothing here vouches for a
prover backend's own soundness.

The `+proven+` rows — R2, R4, R9, R10, R11 — each name the kernel, the
receipt and the limit that qualify them (R2 the receipt-time escape-hatch
audit, R4 the `+UnsupportedIndexedMatch+` caveat, R9 the digest-level scope).
R3 stays `+open+`: its Lean build passes, but Lean is not the verifier §1
assigns to those statements until the placement is decided. Only theory theorems are graded (§8.1): R11 is at
`+PWG-3+`; the engineering rows carry no PWG. Every *independent* leg is still
`+open+`: R5 has never been attempted, which is why nothing here is above
`+PWG-3+`. Proven in one kernel is exactly what `+PWG-3+` means, and neither fact
is an omission.
