=== P0 — Licensing: the 2026-08-07 resolution (superseded by D262)

*Was:* the repository stated four different licences at once —
`+LICENSE+` and `+Cargo.toml+` said AGPL-3.0-or-later while 590 source
files granted MPL-2.0, `+NOTICE+` described the project as MPL-2.0 while

`+PMPL-1.0 AND Palimpsest-0.6+`. Because per-file SPDX headers are
themselves a licence grant, a recipient could have taken the tree under
MPL-2.0 — which, unlike AGPL, has no network clause.

*Now:* reconciled to the owner’s AGPL ruling as a deliberate three-part
split.

[width="100%",cols="34%,33%,33%",options="header",]
|===
|Part |Licence |Files
|Code — `+src/+`, `+crates/+`, `+ffi/+`, `+proofs/+`, `+spark/+`,
`+verification/+`, build system, CI, machine-readable metadata
|*AGPL-3.0-or-later* |594 + 6 dual

|*CC-BY-SA-4.0* |92 + 1 dual

|`+echidna-playground/+` — Coq-Jr sub-project |*MPL-2.0*, unchanged |35

The playground was *not* relicensed: it carries contributions attributed
to "`Coq-Jr Contributors`", and relicensing another party’s work needs
their consent. It does not need relicensing — MPL-2.0 §3.3 designates
the GNU licences (including AGPL-3.0+) as Secondary Licenses, so MPL
files combine into an AGPL work and the combined work distributes under
AGPL while those files individually remain available under MPL. No file
carries the Exhibit B "`Incompatible With Secondary Licenses`" notice
that would break this.

`+NOTICE+` and `+.reuse/dep5+` were rewritten to describe the split;
`+LICENSE+` had two prepended SPDX lines removed so it is byte-identical
to `+LICENSES/AGPL-3.0-or-later.txt+` — those lines were stopping
GitHub’s licence detector matching the body, which is why the repository
showed "`Other`".

*Verification as it stood on 2026-08-07 (historical; inverted by D262 —
use the check in the current section above):*

[source,bash]
----
# no MPL outside the playground and licence reference material
git grep -l 'SPDX-License-Identifier:.*MPL-2\.0' \

# GitHub now detects a licence

==== D9. Solver integrity is documented as enforced and is not enforced

*P1.* `+docs/ARCHITECTURE.adoc+` and the published site listed solver binary
integrity as step 1 of the trust pipeline. The check is conditional
(`+dispatch.rs:632+`): with no checker attached, `+solver_integrity_ok` is
`true`. `+with_integrity_checker+` has no caller in the tree, and
`+config/solver-manifest.toml+` holds `+PLACEHOLDER_COMPUTE_ON_FIRST_RUN+` for
every solver. An installed binary with a placeholder digest reports
`+Uninitialized+`, which the dispatch code permits; an absent binary reports
`+Missing+`. Neither outcome is a verified binary identity.

Fixed so far: the docs and the published site now say "capability present, not
currently engaged" instead of claiming a step that does not run.

Now machine-checked on the specification side:
`+meta-checker/src/Echidna/Integrity.agda+` (`+docs/PROOF-STATUS.adoc+` R9)
proves that verification in its model requires an initialised manifest and
that an uninitialised manifest never verifies. Its explicit hypothesis is
digest-comparison soundness: an accepted comparison implies equal digests.
The model has no binary contents or hashing function, so it does not prove
content-level collision resistance and cannot distinguish equal-digest
substitutions. The sharpness theorem directly refutes comparator soundness
for an accept-everything comparator.

The accepting Rust branches in `+dispatch.rs+` and
`+integrity/solver_integrity.rs+` are established by source comparison. The
Agda model has no dispatch-permission decision and no machine-checked
refinement connecting it to those branches. Closing D9 requires an explicit
runtime policy, correct wiring, non-placeholder manifests and execution tests;
the model theorem alone does not enforce that policy.

Open: decide whether to wire it (introducing a refuse-on-mismatch failure mode)
or to delete the step from the pipeline description. Recorded rather than
silently changed.

[source,bash]
----
rg -n 'with_integrity_checker|IntegrityStatus::Uninitialized|solver_integrity_ok' src/ crates/ tests/
rg -n 'PLACEHOLDER' config/solver-manifest.toml
# After the pinned setup in scripts/ci/setup-agda.sh:
bash scripts/ci/check-agda.sh
