= ECHIDNA Container Ecosystem (Stapeln)

== Overview

ECHIDNA uses the Stapeln container ecosystem for production deployment.

== Files

[cols="1,2"]
|===
| File | Purpose

| `Containerfile` | Multi-stage OCI build (Chainguard wolfi-base)
| `compose.toml` | selur-compose orchestration (app + svalinn gateway)
| `.gatekeeper.yaml` | Svalinn edge gateway policies
| `entrypoint.sh` | Container entrypoint with signal handling
| `vordr.toml` | Vordr runtime monitoring configuration
| `manifest.toml` | Cerro-torre .ctp bundle metadata
| `ct-build.sh` | Build/sign/verify pipeline
| `deploy.k9.ncl` | k9-svc deployment (Hunt trust level)
|===

== Quick Start

The image, compose and K9 probes use `+/api/health+`. A successful response
establishes that the core HTTP process is responding. The handler does not
check solver availability, dispatcher readiness or dependent services, so
the K9 readiness field has a process-level contract. Deployments that gate
traffic on those dependencies must check them separately.

The K9 file is a Hunt-level deployment template. Its placeholder signature,
placeholder checksum and `+hunt_authorized = false+` are not deployment
authorization. The repository's K9 CI hook checks structural fields; it does
not verify a cryptographic signature or evaluate Nickel.

[source,bash]
----
# Build
just container-build

# Start stack
just container-up

# Full pipeline (build + sign + verify)
just container-pipeline

# Stop
just container-down
----
