=== [Unreleased]

==== Added — structural cross-prover identity keys, 2026-10-22

* *`+src/rust/corpus/canonical.rs+`* — normalises a declaration's *type*
  into a nameless prefix term (variables renamed `+v0, v1, …+`, module
  qualifiers dropped, operator spellings and binder keywords canonicalised,
  sorts mapped to `+NAT+`/`+INT+`/`+TYPE+`/…, ascriptions unwrapped) and
  hashes it with SHA-256 under scheme `+dk-shape-v1+`. No dictionary and no
  per-prover naming convention is consulted.
* *`+DeclGraph+`* gains `+cross_prover_identity_key+`,
  `+cross_prover_skeleton_key+` (binders and sorts erased — the tier-2 join
  for Isabelle and Why3), `+identity_scheme+` and `+canonical_type+`. All
  are `+#[serde(default)]+`, so existing octad files still load;
  `+cross_prover_id+` (the name-tail hash) is still emitted for
  compatibility.
* *`+GraphPayload+`* (VeriSim bridge) and `+QueryResultEntry+` (VCL-UT)
  carry the structural key through to consumers.
* *`+echidna corpus identity <pattern>+`* — groups declarations by
  structural key, with `+--skeleton+` (print the tier-2 key) and
  `+--cross-only+` (only groups spanning several adapters).

==== Changed — structural 256-dim Vector octad, 2026-10-22

* The default embedder is now `+StructuralEmbedder+`: 1–3-grams of the
  canonical type atoms hashed into *256* buckets (L2-normalised, model
  `+echidna-corpus-structural-v2+`). `+corpus near+` canonicalises the
  query first, so a query written in one prover's syntax retrieves entries
  written in another's.
* `+HashEmbedder+` (32-dim, `+echidna-corpus-hash-v1+`) remains available
  as `+Corpus::compute_embeddings_legacy+` for GNN `+FEATURE_DIM+` parity
  and for replaying octads written before this change. The capnp
  `+embedder+` / `+embedder_dim+` fields carry both, and consumers must
  compare them before comparing vectors.
* Supersedes the embedder half of D6 in
  `+docs/decisions/2026-04-28-corpus-and-design-search.adoc+`; the decision
  record is annotated in place.

==== Added — corpus adapters for the estate's own TCB languages, 2026-10-22

* *`+src/rust/corpus/spark_ada.rs+`* — Ada/SPARK adapter (`+*.ads+` /
`+*.adb+`). Extracts packages, `+with+`/`+use+` clauses, subprograms with
their `+Pre+`/`+Post+`/`+Contract_Cases+`/`+Global+`/`+Depends+` aspects, and
the GNATprove escape hatches: `+pragma Assume+` (and the old `+--# assume+`
form) is reported as a *postulate*, plus `+pragma Annotate+` proof
disabling, `+pragma Suppress+`, `+Unchecked_Conversion+`, `+pragma Import+`
and `+SPARK_Mode => Off+`. Recognises the sparklib `+Lemma_*+` + `+Ghost+`
lemma convention as `+sparklib:lemma+` so reusable lemmas are separable
from executable subprograms. Spec and body are paired across files into
one entry (unambiguous pairs only).
* *`+src/rust/corpus/creusot.rs+`* — Rust/Creusot adapter (`+*.rs+`).
Folds `+#[requires]+`, `+#[ensures]+`, `+#[invariant]+`, `+#[variant]+`,
`+#[logic]+`, `+#[predicate]+` and `+#[cfg(creusot)]+` into the entry's
statement, and tags `+pearlite!+`, `+proof_assert!+`, `+snapshot!+`,
`+unsafe+`, `+transmute+` and `+extern "C"+`. `+#[trusted]+` is reported as
a postulate, because Creusot accepts the contract and skips the body.
`+#[test]+` / `+#[cfg(test)]+` items are excluded: a corpus of proofs
should not be dominated by test functions.
* *`+src/rust/corpus/profile.rs+`* + `+data/corpus-profiles/hyperpolymath-estate.toml+`
— the `+hyperpolymath_estate+` profile: every repository's `+src/abi+`
Idris2 tree (a `+name = "*"+` rule, so new repos are picked up without a
manifest change) plus the five Agda type libraries (`+echo-types+`,
`+epistemic-types+`, `+secret-types+`, `+tropical-types+`,
`+choreographic-types+`). Sub-trees are indexed by their own adapters,
then merged with `+repo::+` name prefixes and `+repo:+` / `+layer:+` module
tags. `+ECHIDNA_ESTATE_MANIFEST+` overrides the manifest path.
* *`+Corpus::reindex_links()+`* — split out of `+reindex()+` so a merge can
rebuild the lookup maps without re-running discipline detection under the
merging adapter's name.
* *`+crates/echidna-core-creusot/src/estate_layers.rs+`* — Creusot-annotated
layer classification (PO-L1..L5): totality, partition, and the checkable
form of "every ABI is Idris2". Stated, not proved, like the rest of that
crate; the stable-Rust tests mirror every obligation.
* *`+_verification_systems.toml+`* +8 rows for the syntax the new adapters
detect (`+pragma_assume+`, `+contract_cases+`, `+spark_mode+`,
`+ghost_lemma+`, `+trusted_attribute+`, `+pearlite+`, `+proof_assert+`,
`+variant_clause+`), so the semantic layer can resolve what the indexer
reports.
* Corpus adapters: 17 → *20*. Open backlog re-ordered: `+iris.rs+` and
`+tlaps.rs+` to the top (separation logic for the Zig/Rust layers;
temporal proofs for the Elixir/OTP and SNIF layers), `+alphaproof.rs+` and
`+naproche.rs+` to the bottom (no published corpus or file format, and no
estate vocabulary).

==== Added — verification vocabulary 2026-10-22

* *`+data/synonyms/_verification_systems.toml+`* (665 rows): the first
cross-prover dictionary aimed at program verification rather than
undergraduate pure mathematics. Sections: bitvectors and machine integers,
memory layout and ABI, ownership and slicing, separation logic and region
framing, contracts and proof obligations, termination measures, refinement
and semantics, resource algebras (dioid / tropical / antichain /
fixpoint), information flow and epistemic vocabulary, concurrency, and the
estate layer boundaries. Loaded as
`+CrossProverDicts::verification_systems+` (Rust) and
`+SaturationSynonyms.load_verification_systems+` (Julia).
* *`+_msc2020.toml+`* 87 -> *181* codes. 68Qxx (26 codes) and 68Nxx (10
codes) are now complete; 03B/03C/03D/03F cover logic, computability and
proof theory; 68M/68P/68T/68V/68W and 06B35 cover the systems and proof
assistant ring. Nineteen pre-existing rows had MSC2010 or transferred
wording and are repaired in place, with a note naming the MSC2020 code
(`+03B15+` -> 03B16/03B38, `+68T15+` -> 68V15, `+68V05+`/`+68V25+`/
`+68V30+`/`+68V35+` re-pointed to their current meanings).
* *Consumer wiring*: `corpus crossquery` now searches the cross-prover
dictionaries as well as the per-prover tables, so `crossquery frame-rule`,
`crossquery estate-snif` or `crossquery 68Q60` resolve; `--provers-only`
restores the old scope. `CrossProverDicts::tables()/len()` and
`SynonymTable::merge_cross_prover_dicts()` added. The Julia training
launcher pre-loads all five dictionaries at launch.
* *`+idris2.toml+`* 6 -> *26* rows: `Fin`, `Bits8/16/32/64`, `Int8..64`,
`Vect`, `So`, `LTE`, `Dec`, `cast`, totality annotations, `%foreign`,
`export`, `Prim__`, `Ptr`, `IO`, `Ref`, multiplicities and erasure — the
vocabulary the Idris2 ABI layer is written in.
* *More MSC repairs*: `18N40`, `18G80`, `18D05` and `14F08` corrected
against zbMATH (18N40 is model categories, not HoTT; 18G80 is derived
categories, not infinity-categories; 18D05 is MSC2010-only and moved to
18N10). Added 18G35, 18M05, 18N45 and 18N60; MSC total 181.
* *Doc mirrors*: the wiki pages named a `SynonymTable::with_msc2020()`
API that never existed; they now use the real loader. Wiki/architecture
pages updated to the five-dictionary reality.
* *Estate language policy* recorded in `+data/synonyms/README.adoc+`:
ABIs in Idris2, APIs and FFIs in Zig, BEAM native boundaries as SNIFs
(not bare NIFs), Rust/Creusot for the Rust layer, Julia and Chapel for
their layers, and no Python anywhere in the tree.

==== Added — arbitration 2026-10-14 (ECH-05)

* *Fidelity-levelled arbitration*: `+ProverAttempt+` carries
`+FidelityEvidence+` (`+KernelTranslation+` / `+DeclaredCorrespondence+` /
`+None+`) and `+ArbitratedVerdict+` gains `+level+` (`+belief+` / `+epi+` /
`+sound+`), `+retracted+` and `+warranted_term+`. `+sound+` needs every
fused attempt to be a kernel-checked translation to one exchange-layer
term (`+exchange::term_hash+`); a synonym collision stays `+belief+`
however many backends agree. `+ResultArbiter::retract+` marks a backend
unsound and lowers every verdict that rested on it. Numeric fusion is
unchanged: `+tests/arbitration_regression_test.rs+` replays the
pre-change numbers. Dispatch attaches no evidence yet, so dispatched
verdicts are `+belief+`.
* *`+EchidnaABI.Arbitration+`* (Idris2): the three-level verdict as a
closed sum whose `+Sound+` constructor carries the hash-equality proofs,
with the classifier and its properties; `+tests/abi/{accept,reject}+`
fixtures checked by `+scripts/abi-fixtures.sh+` in `+idris2-abi-ci.yml+`.

* *Three broken Idris2 proofs repaired* (5/5 now type-check):
** `+AxiomCompleteness.idr+`: 23× `+prf = impossible+` (invalid RHS)
rewritten to `+Refl impossible+`.
** `+DispatchOrdering.idr+`: rewritten as a minimal working proof
(6-stage dispatch pipeline with LT witnesses for adjacent stages).
Original had invalid constructor signatures with named args in
return-type position.
** `+ProverKindInjectivity.idr+`: replaced 48×
`+lteSuccRight $ ... $   LTERefl+` chains (unification failed) with
direct `+LTESucc (...)+` constructor nesting. Type signature switched
from `+maxDiscriminant+` alias to literal `+48+` so Idris2 can unfold
`+S ?right+`. Added `+import Data.Nat+`.
* *Agda scoping bugs* in `+Basic.agda+`, `+List.agda+`, `+Nat.agda+`,
`+Propositional.agda+`: files defined datatypes inside `+where+`
clauses, putting them out of scope for outer signatures. All four
rewritten as clean agda-stdlib-backed proofs (5/6 `+.agda+` files now
compile).
* *TPTP precedence* in `+proofs/tptp/transitivity.p+`: added explicit
parens around `+(lt(X,Y) & lt(Y,Z))+` before `+=>+` so E Prover parses
it. Now Theorem-certified by both Vampire and E Prover.
* *`+/api/verify+` false-positive guard*: server-level check in
`+prove_handler+` and `+verify_handler+` now returns `+valid: false+`
when `+parse_string+` produces an empty `+ProofState+` (no goals,
theorems, definitions, axioms, or variables) on non-empty input. Partial
fix for the parse+export round-trip bug documented in `+TEST-NEEDS.adoc+`.
Verified live: garbage to Coq/Lean now returns `+valid: false+` (was
`+true+`); real proofs unaffected.
* *Isabelle prover backend de-stubbed*
(`+src/rust/provers/isabelle.rs+`). `+parse_string+` previously
discarded its `+content+` argument and always emitted a single
`+Term::Const("True")+` goal, which `+verify_proof+` then
short-circuited to `+Ok(true)+` — Isabelle was never actually invoked.
It now extracts the theory name and top-level
`+theorem|lemma|corollary+` declarations with nested-comment-aware
scanning, stashes the raw `+.thy+` content in
`+ProofState.metadata["raw_thy_content"]+`, and `+verify_proof+` writes
that content to a unique per-invocation temp directory under the correct
filename (Isabelle requires `+<theory_name>.thy+`) before invoking
`+isabelle process -l Main -e 'use_thys ["<path>"]'+`.
* *Stale scaffolded temp-file path* in Isabelle’s fallback verification
path: previously wrote `+echidna_verify.thy+` containing
`+theory GeneratedProof+`, causing filename/theory-name mismatch
rejection by `+isabelle build+`. Now writes `+GeneratedProof.thy+` in a
unique temp dir.

==== Added

* `+strip_isabelle_comments+` helper for the Isabelle backend (handles
nested `+(* ... *)+` blocks).
* 9 new unit tests for the Isabelle theory-header parsers
(`+test_strip_*+`, `+test_extract_theory_name_*+`,
`+test_extract_lemma_names_*+`) and the `+parse_string+` contract
(metadata populated, goals non-trivial, context theorems enumerated,
empty-theory fallback goal).
* Parser verified against a real 788-line `+Tropical.thy+` (tropical
semiring formalisation): extracts theory name and all 55
theorems/lemmas.

==== Notes

* Deployment of this fix to `+echidna-nesy+` on Fly.io requires
rebuilding the container with the `+isabelle+` binary on `+$PATH+`.
Without it, `+verify_proof+` returns `+Ok(false)+` with a
`+"Failed to run Isabelle   process"+` context error.
* Audit of all 50 prover backends confirmed Isabelle was the only truly
stubbed one. `+metamath.rs+` and `+typed_wasm.rs+` are intentionally
pure-Rust in-process verifiers (no subprocess needed by design). The
remaining 47 external-solver backends all spawn real solver subprocesses
via `+Command::new+`.
