==> echidna --help <==
Neurosymbolic theorem proving platform with multi-prover support

Usage: echidna [OPTIONS] <COMMAND>

Commands:
  prove         Prove a theorem from file
  verify        Verify an existing proof
  search        Search theorem libraries
  interactive   Start interactive REPL mode
  server        Start HTTP API server
  list-provers  List available provers
  info          Show information about a specific prover
  diagnostics   Interactive diagnostics REPL for health monitoring
  corpus        Build / query a project corpus (named decls + dependency DAG)
  lexicon       Mine lexicon candidates across training corpora (flag-only)
  design        Search proof-design space via simulated annealing
  suggest       Suggest tactic variants that close a failing lemma
  help          Print this message or the help of the given subcommand(s)

Options:
      --format <FORMAT>  Output format (text, json) [default: text]
  -v, --verbose          Verbose output
      --no-color         Disable colors
  -h, --help             Print help
  -V, --version          Print version

          Possible values:
          - human: Human-readable report (the default)
          - json:  One `echidna.prove.result/1` JSON object on stdout
          
          [default: human]

  -h, --help
          Print help (see a summary with '-h')

==> echidna corpus --help <==
Build / query a project corpus (named decls + dependency DAG)

Usage: echidna corpus [OPTIONS] <COMMAND>

Commands:
  ingest         Walk a project tree and build a corpus index
  query          Query a previously-ingested corpus index
  stats          Print summary statistics for a corpus index
  crossquery     Look up entries across every synonym table by `semantic_class`. Demonstrates cross-prover semantic equivalence: `corpus crossquery well-foundedness` reports `WellFounded` in Agda, `well_founded` in Coq, and `WellFounded` in Lean and Idris 2
  near           Find the K nearest-neighbour entries to a free-form text query by cosine similarity over the Vector octad embeddings. The query is canonicalised the same way the corpus is, so a statement written in one prover's syntax matches entries written in another's. Useful for "find lemmas structurally near `WellFounded _<_`"
  identity       Group matching declarations by their *structural* identity key
  export-octads  Convert a JSON corpus index into 8-modality octad JSONL (one DeclarationOctad per line). Streamable; compatible with VeriSim's `/api/v1/octads` endpoint when posted line-by-line
  import-octads  Load an octad JSONL stream back into a corpus and persist as JSON. Round-trip is best-effort but lossless for the fields the corpus cares about (statements, proofs, deps, hazards)
  help           Print this message or the help of the given subcommand(s)

Options:
      --format <FORMAT>  Output format (text, json) [default: text]
  -v, --verbose          Verbose output
      --no-color         Disable colors
  -h, --help             Print help

==> echidna corpus crossquery --help <==
Look up entries across every synonym table by `semantic_class`. Demonstrates cross-prover semantic equivalence: `corpus crossquery well-foundedness` reports `WellFounded` in Agda, `well_founded` in Coq, and `WellFounded` in Lean and Idris 2.

The cross-prover dictionaries are searched too, so classes that only exist there (`wrapping-arithmetic`, `frame-rule`, `estate-snif`, or an MSC code such as `68Q60`) resolve.

Usage: echidna corpus crossquery [OPTIONS] <CLASS>

Arguments:
  <CLASS>
          Semantic class to look up (e.g. `well-foundedness`)

Options:
      --format <FORMAT>
          Output format (text, json)
          
          [default: text]

      --synonyms-dir <SYNONYMS_DIR>
          Synonym directory (defaults to `data/synonyms`)

      --provers-only
          Only search the per-prover tables, skipping the cross-prover dictionaries

  -v, --verbose
          Verbose output

      --no-color
          Disable colors

  -h, --help
          Print help (see a summary with '-h')

==> echidna corpus identity --help <==
Group matching declarations by their *structural* identity key.

The key is the SHA-256 of the type's canonical shape — variable names, module paths, operator spellings and binder keywords are normalised away — so `+-comm` in Agda, `Nat.add_comm` in Lean and `eq Nat (add x y) (add y x)` in Dedukti land on one key with no synonym lookup. `--skeleton` additionally prints the binder- and sort-free key, which is what provers that elide binders (Isabelle) match on.

Usage: echidna corpus identity [OPTIONS] <PATTERN>

Arguments:
  <PATTERN>
          Name pattern to match: a substring of the qualified or short name, case-insensitive. `*` matches every declaration

Options:
      --format <FORMAT>
          Output format (text, json)
          
          [default: text]

  -i, --index <INDEX>
          Path to the corpus JSON. Defaults to `data/corpus/<basename>.json` for the cwd's basename

      --skeleton
          Also print the skeleton key (binders and sorts erased)

  -v, --verbose
          Verbose output

      --cross-only
          Only show keys that group declarations from more than one adapter

      --no-color
          Disable colors

  -h, --help
          Print help (see a summary with '-h')

Pair theorem names and canonical statement shapes across training corpora and write review candidates as JCS JSON Lines. Every candidate carries `evidence = none`; `data/synonyms/` is never edited

Usage: echidna lexicon scan [OPTIONS]

Options:
      --format <FORMAT>
          Output format (text, json) [default: text]
      --training-dir <TRAINING_DIR>
          Directory holding `proof_states_<corpus>.jsonl` files [default: training_data]

      --collision-samples <COLLISION_SAMPLES>
          Key-collision groups to sample per corpus [default: 40]
