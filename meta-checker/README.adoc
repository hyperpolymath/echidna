== Overview

The meta-checker is an *Agda model* of ECHIDNA's trust-hardening pipeline. It
states properties of that model and proves them. A successful check means the
model has those properties. It does not establish that the Rust implementation
has them: no refinement between these definitions and the Rust source is proved
here. Verifying the Rust is the job of Creusot with Pearlite contracts and Verus
(`+PROOF-POLICY+` §1.2), recorded as obligation R1 in
link:../docs/PROOF-STATUS.adoc[`+docs/PROOF-STATUS.adoc+`].

That file is the authoritative record of what is proved, by which receipt, and
with which limits. This README describes the modules and how to check them.

The model does not match the Rust everywhere, and some theorem names promise more
than their statements give. The design review under R4 in `+PROOF-STATUS+`
lists each case: for example, the dispatch model gives Level 2 where the Rust
gives Level 3, and `+comment-skip-sound+` ignores its hypothesis. Until the
Rust contracts replace these modules, read each statement, not its name.

== Modules

[cols="1,3",options="header"]
|===
|Module |What it states

|`+Echidna.TrustLevel+`
|The five trust levels form a total order; `+min-trust+` is a lower bound;
dangerous axioms cap trust at Level 1; capping is monotone.

|`+Echidna.AxiomSafety+`
|Axiom policies form a total preorder; `+worst-policy+` is commutative and
associative with `+Clean+` as identity; `+Rejected+` is absorbing; every danger
class maps to exactly one policy.

|`+Echidna.Portfolio+`
|Cross-checking does not lower trust below a single solver; inconclusive and
timed-out results give Level 1; agreement is reflexive and symmetric; unknown
verdicts never count as agreement.

|`+Echidna.Dispatch+`
|Failed integrity and dangerous axioms each give Level 1; Level 5 needs every
positive factor; the modelled pipeline only degrades trust and is deterministic.

|`+Echidna.AxiomTrackerCompleteness+`
|Every registered pattern yields exactly one policy; the policy fold
distributes over registry concatenation and is monotone; an empty registry
yields `+Clean+`; a `+Reject+` pattern anywhere forces `+Rejected+`; scanning is
deterministic.

|`+Echidna.Integrity+`
|Obligation E11 over digests: verification needs an initialised manifest, means
the recorded digest matched, and never accepts a different digest. Digest
comparison soundness is a record field, not a postulate.

|`+Echidna.ClampTrust+`
|Bounds, monotonicity, fixed points and idempotence of a modelled
`+clamp-trust : ℕ → TrustLevel+`. No such function exists in the Rust (R10).

|`+Echidna.Receipt+`
|A two-world Kripke countermodel separating receipts (factive) from warrants
(not factive). This is the module's one *theory* statement under §1.

|`+Echidna.MetaChecker+`
|The entry point that imports the eight modules above.
|===

Under `+PROOF-POLICY+` §1 only `+Receipt+` is theory. The other modules state
properties of this repository's own types, which §1 places with Idris 2. The
owner's decision of 2026-11-09 splits them. What holds for any implementation
stays as Agda theory. The echidna-specific statements are verified on the Rust
with Creusot/Pearlite and Verus, not restated in Idris 2, and each module here
retires once its contracts carry a receipt. See R4 in
`+docs/PROOF-STATUS.adoc+`.

== Escape hatches

The check runs with `+--safe+`, so the compiler refuses `+postulate+`,
`+primTrustMe+` and unsafe options anywhere in the import cone. There are no
postulates in these modules. The kernel enforces that; a text search is not the
evidence.

The check reports `+UnsupportedIndexedMatch+` warnings at a few sites. They mean
the flagged functions do not compute under Cubical transports, which is the
difference between `+--cubical-compatible+` and full `+--cubical+` that
`+PROOF-POLICY+` §2.1 draws. They are recorded in `+PROOF-STATUS+`, not
suppressed.

== Running

Use the pinned toolchain and the canonical invocation (`+PROOF-POLICY+` §2.1).
The scripts install Agda 2.7.0.1 and agda-stdlib 2.1 from release archives
checked against pinned SHA-256 digests, then check every module and require a
fresh interface for each one:

[source,bash]
----
bash scripts/ci/setup-agda.sh     # prints the paths to export
bash scripts/ci/check-agda.sh     # runs from meta-checker/
----

`+check-agda.sh+` runs:

[source,bash]
----
agda --no-default-libraries --library-file "$AGDA_LIBRARIES_FILE" \
  --safe --without-K --cubical-compatible src/Echidna/MetaChecker.agda
----

It then fails if any module under `+src/Echidna/+` produced no interface, and runs
`+scripts/ci/check-receipt-controls.sh+`, whose planted claims must be rejected.

== CI

`+.github/workflows/agda-meta-checker.yml+` runs the same two scripts on relevant
pushes and pull requests and on a schedule. A passing run on a commit is that
commit's receipt for the Agda leg; `+PROOF-STATUS+` cites it by run and commit.
